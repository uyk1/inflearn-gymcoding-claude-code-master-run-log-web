# PRD: Run Log (v2)

> v1(MVP) PRD는 [prds/PRD-v1.md](prds/PRD-v1.md)에 보관되어 있습니다. 이 문서는 관리자 페이지(v2)까지 포함한 현재 PRD입니다.

## 1. 프로젝트 개요

- **프로젝트명**: Run Log
- **목적**: Notion을 CMS로 활용해 러닝 기록을 쌓고, 웹에서 조회·분석해 훈련에 도움을 받는다. v2에서는 웹 관리자 페이지에서 기록을 안전하게 입력·수정·삭제할 수 있게 한다.
- **CMS 선택 이유**: Notion API를 활용하면 별도 데이터베이스 없이 기록을 쌓을 수 있고, 노션 앱에서 직접 입력하거나 고쳐도 웹에 반영된다. 노션이 계속 데이터 원본이며, v2의 관리자 페이지는 노션 앱과 나란히 쓰는 **보조 입력 경로**다. 폰에서 바로 입력하고, 입력 오류로 기록이 제외되는 일을 막는 것이 목적이다.
- **버전 구성**
  - **v1(MVP)**: 읽기 전용 조회, 통계, PWA 설치. 2026-11-05에 완료되어 https://pjt-run-log.vercel.app 에 배포되어 있다.
  - **v2**: 관리자 페이지(인증, 기록 입력·수정·삭제, 제외 행 고치기). 구현 순서와 진행 상태는 [ROADMAP.md](ROADMAP.md)에 있다.

## 2. 주요 기능

**v1 구현됨**

1. 러닝 기록 목록: 날짜순 조회, 기간 필터
2. 러닝 기록 상세: 거리·시간·페이스·메모 확인
3. 통계 대시보드: 주간·월간 거리, 시간, 평균 페이스 추이
4. PWA 설치: 갤럭시(Chrome, Samsung Internet)와 아이폰(Safari)의 홈 화면에 추가해 독립 앱처럼 실행 (아이폰 Safari 실기기 확인, 갤럭시는 확인하지 않음)

**v2 추가**

5. 관리자 인증: 로그인한 관리자만 관리자 화면과 쓰기 동작을 쓸 수 있다.
6. 기록 입력: 웹 폼에서 기록을 만든다. 입력 검증은 읽기와 같은 규칙을 쓴다.
7. 기록 수정·삭제: 기록을 고치고, 삭제는 노션 휴지통으로 보내 복구할 수 있게 한다.
8. 제외 행 고치기: 입력 오류로 목록에서 제외된 행을 수정 화면에서 바로 고친다.

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 15.5 (App Router), React 19 | 이미 설치됨 |
| 언어 | TypeScript | 프로젝트 표준 |
| 스타일 | Tailwind CSS 4, shadcn/ui (base-nova) | 이미 설치됨 |
| 아이콘 | Lucide React | 이미 설치됨 |

| CMS | Notion API, `@notionhq/client` v5 | v1은 `dataSources.query`로 조회. v2에서 페이지 생성·수정·휴지통 이동 추가 |
| 차트 | recharts | 통계 화면용. v1에서 shadcn `chart` 컴포넌트와 함께 사용 확인 |
| PWA | Next.js `app/manifest.ts`, 아이콘(192·512 PNG), `apple-touch-icon` | 별도 패키지 없이 구현. service worker는 제외 |
| 인증 (v2) | 환경 변수 비밀번호 + 서명 쿠키 세션 | Phase 1에서 결정. 세션은 3일(Phase 6에서 7일에서 단축)이며 서버에서 폐기할 수 없고 만료나 비밀값 교체로만 무효화된다 |
| 테스트 (v2) | Node 내장 test runner (`node --test`) | 새 패키지 없음. 입력 검증, 소요시간·날짜 규칙 같은 순수 함수를 단위 테스트한다. 테스트 대상 모듈은 `@/` 별칭 대신 상대 경로로 import한다 |

**환경 변수**

- `NOTION_API_KEY`: 공개 조회용 서버 전용 Notion 통합 키. 읽기 전용 권한이며 접두사가 없다.
- `NOTION_ADMIN_API_KEY` (v2): 관리자 쓰기용 Notion 통합 키(읽기, 삽입, 수정 권한). 공개 조회용 읽기 전용 키와는 코드 경로와 환경 변수를 분리하며, 쓰기 권한이 있는 기존 개발용 통합을 재사용할 수 있다. 서버 전용이며 접두사가 없고 배포 플랫폼의 Production에만 등록한다.
- `NOTION_DATA_SOURCE_ID`: 러닝 기록 데이터 소스 ID. DB ID가 아니라 data source ID를 사용한다.
- `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` (v2): 관리자 로그인 비밀번호와 세션 서명 비밀값(32자 이상). 서버 전용이며 접두사가 없고 배포 플랫폼의 Production에만 등록한다. 값은 코드와 저장소에 기록하지 않는다.

## 4. Notion 데이터베이스 구조

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | title | O | 기록 제목 (예: "한강 아침 러닝") |
| 날짜 | date | O | 러닝한 날짜. 통계와 정렬의 기준이므로 필수. 비어 있는 기록은 제외. 시간을 포함해 입력해도 한국 시간 기준의 날짜(`YYYY-MM-DD`)로 처리하고, 날짜 형식이 올바르지 않으면 제외 |
| 거리(Km) | number | O | 이동 거리 (km) |
| 소요시간 | rich_text | O | `mm:ss` 또는 `h:mm:ss` 형식으로 입력하고, 초와 `h:mm:ss`의 분은 두 자리로 씁니다 (예: `45:23`, `5:03`, `1:05:03`). 앱에서 초로 변환 |
| 장소 | rich_text | - | 코스 또는 장소 |
| 강도 | select | - | EASY / NORMAL / HARD |
| 메모 | rich_text | - | 자유 메모 |
| 태그 | multi_select | - | 예: 인터벌, 장거리, 회복 |
| 출처 | select | - | 수동 / NRC / 기타. 웹 입력은 항상 "수동"으로 저장한다(v2 Phase 2에서 결정, 기존 옵션이라 노션 DB 구조를 바꾸지 않음) |
| 외부ID | rich_text | - | 외부 앱 연동 시 원본 기록 식별자. 웹 입력은 폼이 제출마다 만드는 고유 키를 `web-<UUID>`로 저장해 중복 입력을 막는다(v2 Phase 2에서 결정, 같은 키가 이미 있으면 새로 만들지 않고 기존 기록을 돌려준다) |

**계산 규칙**
- 평균 페이스(km당 시간)는 노션에 저장하지 않고 웹 앱에서 계산합니다. 소요 시간을 초로 바꾼 뒤 거리로 나누고, `mm:ss` 형식으로 표시합니다.
- 필수 값(제목, 날짜, 거리, 소요시간) 중 하나라도 비어 있거나 형식이 틀리면 해당 기록은 목록에서 제외하고 로그를 남깁니다. 제외된 기록은 화면에서 제목, 사유, 노션 원본 링크를 확인할 수 있게 안내합니다. 제목을 제외한 입력값(날짜, 거리, 소요시간 원문 등)은 공개 화면에 보여 주지 않습니다. 로그인한 관리자가 수정 화면을 열었을 때만 그 기록의 입력 원문을 입력칸에 채워 보여 줍니다(제외 목록에는 사유만 보여 줍니다).
- 소요 시간 파싱: `mm:ss` 또는 `h:mm:ss`만 허용합니다. 초는 0~59, 분은 0 이상이어야 합니다. 초와 `h:mm:ss`의 분은 반드시 두 자리로 입력해야 하며(`12:05`는 허용, `12:5`는 제외), 한 자리 입력은 오타로 틀린 값이 들어가는 것을 막기 위해 형식 오류로 봅니다. 형식이 맞지 않으면 해당 기록은 목록에서 제외하고 로그를 남깁니다.
- 거리가 0이거나 소요 시간이 없으면 페이스는 `-`로 표시합니다.
- 관리자 입력 검증(v2): 웹에서 입력·수정할 때도 위 필수 값과 소요시간·날짜 규칙을 읽기와 같은 함수로 검증합니다. 입력할 때 통과한 값이 목록에서 제외되는 일이 없게 하기 위해서입니다.

## 5. 화면 구성

**공개 화면 (v1 구현됨)**

- **홈**: 최근 기록 요약, 이번 주 총 거리, 제외된 기록이 있으면 건수 한 줄 안내
- **기록 목록**: 날짜순 카드 또는 표, 기간 필터, 제외된 기록의 제목·사유·노션 링크 안내(접이식)
- **기록 상세**: 한 건의 모든 필드, 노션 원본 링크
- **통계**: 주간·월간 거리와 페이스 차트

**관리자 화면 (v2)**

- **로그인**: 관리자 인증. 로그인하지 않으면 관리자 화면에 접근할 수 없다.
- **기록 입력**: 모바일 우선 폼. 필드별 오류 안내
- **기록 수정·삭제**: 수정 폼과 삭제 확인 단계. 삭제는 노션 휴지통으로 보낸다.
- **제외 행 고치기**: 관리자 목록의 제외된 기록 섹션에서 수정 화면으로 이동하고, 사유에 해당하는 필드를 강조한다. 공개 화면의 제외 안내에는 관리자 링크를 두지 않는다.

## 6. v2 범위

**포함**
- 관리자 인증과 관리자 화면 보호(서버 측 확인 포함)
- 기록 입력·수정·삭제(휴지통), 읽기와 같은 입력 검증
- 제외된 행을 수정 화면에서 고치기
- 쓰기 직후 공개 화면 갱신(캐시 태그 무효화)
- 공개 상세 화면이 목록과 같은 공유 캐시를 쓰도록 정리
- 쓰기 전용 노션 키 분리와 최소 권한, 입력 검증 단위 테스트

**제외**
- 여러 사용자와 권한 구분(관리자는 1명)
- 영구 삭제(노션 API가 지원하지 않으며, 삭제는 휴지통 이동만 한다)
- 나이키 런 클럽 등 외부 러닝 앱 연동
- 오프라인 캐시(service worker)와 푸시 알림 (향후 확장)
- 관리자 대시보드와 수동 캐시 갱신 버튼 (향후 후보)

**v1에서 넘어온 한계**
- 갤럭시(Chrome, Samsung Internet) 설치와 안드로이드 "앱 설치" 버튼은 기기가 없어 확인하지 않았다. 기기를 구하면 별도로 확인한다.
- `lib/api/response.ts`의 응답 형식(`apiSuccess`, `apiFailure`)은 v1에 API 라우트가 없어 실제 응답으로 확인하지 못했다. v2 쓰기 계층에서 확인한다. (해소: v2 Phase 2에서 `POST /api/admin/runs`의 실제 응답으로 확인)

## 7. 구현 단계

**v1(MVP, 완료)**: 노션 연동과 데이터 계층, 목록·상세, 통계, PWA, 캐싱과 배포, 실기기 확인 순서로 진행했다. 세부 내용은 [roadmaps/ROADMAP-v1.md](roadmaps/ROADMAP-v1.md)에 있다.

**v2**: 준비(PRD·결정) → 인증 → 쓰기 계층 → 기록 입력 → 수정·삭제 → 제외 행 고치기 → 마무리·배포 순서로 진행한다. Phase별 작업과 완료 기준은 [ROADMAP.md](ROADMAP.md)에 있다.

## 8. 비기능 요구사항

- 노션 API 키는 서버 전용으로만 사용하며 브라우저에 노출하지 않는다.
- 공개 조회는 읽기 전용 키를 쓰고, 관리자 쓰기는 별도 키를 쓴다. 쓰기 키는 서버 코드에서만 사용하며 공개 화면 코드가 쓰기 모듈을 import하지 못하게 한다. 쓰기 키는 배포 플랫폼의 Production에만 등록하고 미리보기 배포에는 등록하지 않는다.
- 비로그인 상태의 쓰기 요청은 서버에서 거부한다. 화면 숨김이나 미들웨어만 믿지 않고 쓰기 동작마다 서버 측 세션을 확인한다.
- 노션 API 호출 수를 줄이기 위해 `revalidate`와 공유 캐시를 쓴다. 공개 화면은 같은 조회 캐시를 공유하고, 쓰기 직후에는 캐시 태그로 갱신해 반영 지연을 줄인다.
- 삭제는 노션 휴지통 이동으로만 하며 복구할 수 있어야 한다.
- 쓰기 관련 로그에는 입력값과 키를 남기지 않고, 오류 화면에는 내부 정보를 노출하지 않는다.
- API 응답 형식과 에러 응답 형식을 일관되게 유지한다.
- 모바일 화면에서도 가로 스크롤 없이 보여야 한다. 관리자 화면도 모바일 우선이다.
- 안드로이드(Chrome, Samsung Internet)와 iOS(Safari)에서 설치 후 실행되어야 한다. 아이폰 홈 화면 앱에서도 관리자 로그인이 유지되는지 확인한다. (2026-11-11 아이폰 실기기에서 로그인 유지 확인, 갤럭시는 미확인)
- 설치 후에는 주소창 없이 독립 창으로 실행되어야 한다(`display: "standalone"`).

## 9. 리스크

| 리스크 | 대응 |
|---|---|
| Notion API 호출 제한(rate limit) | ISR 캐싱, 공유 캐시(공개 상세 포함), 페이지네이션 처리 |
| 노션 필드 이름이나 타입 변경 | DTO 매핑 한 곳에서 관리, 필드명 상수화 |
| 노션 입력 누락·오류 값 | 응답 변환 시 기본값 처리, 잘못된 행은 목록에서 제외하고 로그 남김, 웹 입력은 읽기와 같은 규칙으로 검증 |
| 무단 쓰기(인증 없는 접근) | 관리자 인증, 쓰기 동작마다 서버 측 세션 확인, 로그인 실패 횟수 제한, 인증 후에만 쓰기 경로 노출. 세션은 3일, 수정·삭제는 내용 버전 확인으로 낡은 화면과 직접 호출의 오조작을 막는다. 로그인 제한은 서버리스 인스턴스별이라 1차 방어이며 비밀번호를 길게 쓴다 |
| 노션 앱에서 동시에 수정해 덮어쓰는 충돌 | 노션의 마지막 수정 시각이 분 단위라 내용 버전(관리 필드의 정규화 해시)을 비교해 충돌을 알리고 덮어쓰지 않음. 확인과 저장 사이 밀리초 틈은 남는 한계 |
| 쓰기 호출이 호출 제한을 소모 | 쓰기 후 캐시 태그만 무효화하고, 공개 화면은 공유 캐시를 읽음 |
| 읽기와 쓰기의 검증 규칙 불일치 | 같은 검증 함수를 공유하고 단위 테스트로 보호, 노션 쓰기 검증은 `TEST-` 행으로만 |
| 쓰기 키 유출 | 읽기 키와 분리, 최소 권한, 서버 전용, Production에만 등록, 배포 후 번들 패턴 검색으로 노출 확인 |

## 10. 향후 확장

0. **오프라인 캐시와 푸시 알림**: service worker(`@serwist/next` 등)로 마지막으로 본 기록을 오프라인에서 보여 준다. 푸시 알림은 아이폰에서 홈 화면에 설치된 상태에서만 가능하다(iOS 16.4 이상).
1. **NRC 기록 가져오기**: 나이키 런 클럽에서 내보낸 파일을 한 번 가져오는 import 스크립트를 우선 검토한다. 정기 동기화보다 안정적이다. v2에서 만든 쓰기 계층(입력 검증, 노션 쓰기, 외부ID 중복 방지)을 재사용할 수 있다.
2. **공식 API 경유 연동**: Strava, Garmin 등 공식 API를 제공하는 서비스를 거쳐 기록을 가져올 수 있는지 먼저 확인한다.
3. **비공식 API 연동**: 약관과 안정성 위험이 있어 권장하지 않는다.
4. **관리자 대시보드**: 제외된 행과 데이터 품질 현황, 수동 캐시 갱신 버튼 등을 한 화면에 모은다.
5. **보안 후속**: 공유 저장소(Redis 등) 기반의 로그인·쓰기 요청 제한, 서버 측 세션 폐기, CSP 적용을 검토한다. 현재는 인스턴스별 제한, 만료 3일, CSP 없음이 알려진 한계다.

**근거**: 나이키 런 클럽은 공개 API가 없고, 비공식 exporter는 문서화되지 않은 엔드포인트에 의존한다. 사용자 계정의 데이터 내보내기는 일회성이며 수일에서 수주가 걸릴 수 있다. 최신 공식 정책은 확인하지 못했으므로 연동 전 재확인이 필요하다.
