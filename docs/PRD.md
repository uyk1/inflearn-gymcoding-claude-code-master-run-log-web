# PRD: Run Log

## 1. 프로젝트 개요

- **프로젝트명**: Run Log
- **목적**: Notion을 CMS로 활용해 러닝 기록을 쌓고, 웹에서 조회·분석해 훈련에 도움을 받는다.
- **CMS 선택 이유**: Notion API를 활용하면 비개발자도 Notion 표에 기록만 입력하면 웹에 바로 반영된다. 별도 관리자 화면을 만들지 않아도 된다.

## 2. 주요 기능

1. 러닝 기록 목록: 날짜순 조회, 기간 필터
2. 러닝 기록 상세: 거리·시간·페이스·메모 확인
3. 통계 대시보드: 주간·월간 거리, 시간, 평균 페이스 추이
4. PWA 설치: 갤럭시(Chrome, Samsung Internet)와 아이폰(Safari)의 홈 화면에 추가해 독립 앱처럼 실행

## 3. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 15.5 (App Router), React 19 | 이미 설치됨 |
| 언어 | TypeScript | 프로젝트 표준 |
| 스타일 | Tailwind CSS 4, shadcn/ui (base-nova) | 이미 설치됨 |
| 아이콘 | Lucide React | 이미 설치됨 |
| 폼 검증 | zod 4 | 이미 설치됨, 기록 입력 검증 등에 사용 가능 |
| CMS | Notion API, `@notionhq/client` v5 | `dataSources.query`로 조회. 신규 설치 필요 |
| 차트 | recharts | 통계 화면용. 신규 설치 필요. shadcn `chart` 컴포넌트와의 호환은 구현 단계에서 확인 |
| PWA | Next.js `app/manifest.ts`, 아이콘(192·512 PNG), `apple-touch-icon` | 별도 패키지 없이 구현. service worker는 MVP에서 제외 |

**환경 변수**

- `NOTION_API_KEY`: 서버 전용 Notion 통합 키 (접두사 없음)
- `NOTION_DATA_SOURCE_ID`: 러닝 기록 데이터 소스 ID. DB ID가 아니라 data source ID를 사용한다.

## 4. Notion 데이터베이스 구조

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | title | O | 기록 제목 (예: "한강 아침 러닝") |
| 날짜 | date | O | 러닝한 날짜. 통계와 정렬의 기준이므로 필수. 비어 있는 기록은 제외 |
| 거리(Km) | number | O | 이동 거리 (km) |
| 소요시간 | rich_text | O | `mm:ss` 또는 `h:mm:ss` 형식으로 입력 (예: `45:23`, `1:05:03`). 앱에서 초로 변환 |
| 장소 | rich_text | - | 코스 또는 장소 |
| 강도 | select | - | EASY / NORMAL / HARD |
| 메모 | rich_text | - | 자유 메모 |
| 태그 | multi_select | - | 예: 인터벌, 장거리, 회복 |
| 출처 | select | - | 수동 / NRC / 기타. MVP에서는 "수동"만 사용 |
| 외부ID | rich_text | - | 외부 앱 연동 시 원본 기록 식별자. MVP에서는 비워 둠 |

**계산 규칙**
- 평균 페이스(km당 시간)는 노션에 저장하지 않고 웹 앱에서 계산합니다. 소요 시간을 초로 바꾼 뒤 거리로 나누고, `mm:ss` 형식으로 표시합니다.
- 필수 값(제목, 날짜, 거리, 소요시간) 중 하나라도 비어 있거나 형식이 틀리면 해당 기록은 목록에서 제외하고 로그를 남깁니다.
- 소요 시간 파싱: `mm:ss` 또는 `h:mm:ss`만 허용합니다. 초는 0~59, 분은 0 이상이어야 합니다. 형식이 맞지 않으면 해당 기록은 목록에서 제외하고 로그를 남깁니다.
- 거리가 0이거나 소요 시간이 없으면 페이스는 `-`로 표시합니다.

## 5. 화면 구성

- **홈**: 최근 기록 요약, 이번 주 총 거리
- **기록 목록**: 날짜순 카드 또는 표, 기간 필터
- **기록 상세**: 한 건의 모든 필드, 노션 원본 링크
- **통계**: 주간·월간 거리와 페이스 차트

## 6. MVP 범위

**포함**
- Notion DB에서 기록 목록과 상세 조회 (읽기 전용)
- 기본 통계(주간·월간 거리, 평균 페이스). 평균 페이스는 앱에서 계산
- 서버에서만 Notion 호출, 응답 형식 통일, 에러 처리
- PWA 설치 지원: `manifest`(앱 이름, 아이콘, `display: "standalone"`), 아이콘, iOS용 `apple-touch-icon`
- 설치 안내: 안드로이드는 설치 버튼 표시, 아이폰은 "공유 → 홈 화면에 추가" 안내 문구 표시

**제외**
- 로그인·인증
- 웹에서 기록 입력·수정·삭제 (입력은 노션에서 한다)
- 나이키 런 클럽 등 외부 러닝 앱 연동
- 오프라인 캐시(service worker)와 푸시 알림 (향후 확장)

## 7. 구현 단계

1. 노션 DB와 통합(integration) 준비, `.env.example`에 `NOTION_API_KEY`, `NOTION_DATA_SOURCE_ID` 항목 추가
2. Notion 클라이언트와 데이터 계층 구현 (Controller → Service → Repository 구조, DTO, 에러 처리)
3. 기록 목록과 상세 화면 구현
4. 통계 화면 구현 (recharts 설치 포함)
5. PWA 적용: `app/manifest.ts`, 아이콘 세트, metadata의 `apple-touch-icon`, 설치 안내 문구
6. ISR(`revalidate`) 캐싱 적용, 배포
7. 실기기 확인: 갤럭시(Chrome)와 아이폰(Safari)에서 홈 화면 추가 후 독립 창 실행 확인

## 8. 비기능 요구사항

- 노션 API 키는 서버 전용으로만 사용하며 브라우저에 노출하지 않는다.
- 노션 API 호출 수를 줄이기 위해 `revalidate`로 캐싱한다.
- API 응답 형식과 에러 응답 형식을 일관되게 유지한다.
- 모바일 화면에서도 가로 스크롤 없이 보여야 한다.
- 안드로이드(Chrome, Samsung Internet)와 iOS(Safari)에서 설치 후 실행되어야 한다.
- 설치 후에는 주소창 없이 독립 창으로 실행되어야 한다(`display: "standalone"`).

## 9. 리스크

| 리스크 | 대응 |
|---|---|
| Notion API 호출 제한(rate limit) | ISR 캐싱, 페이지네이션 처리 |
| 노션 필드 이름이나 타입 변경 | DTO 매핑 한 곳에서 관리, 필드명 상수화 |
| 노션 입력 누락·오류 값 | 응답 변환 시 기본값 처리, 잘못된 행은 목록에서 제외하고 로그 남김 |

## 10. 향후 확장

0. **오프라인 캐시와 푸시 알림**: service worker(`@serwist/next` 등)로 마지막으로 본 기록을 오프라인에서 보여 준다. 푸시 알림은 아이폰에서 홈 화면에 설치된 상태에서만 가능하다(iOS 16.4 이상).
1. **NRC 기록 가져오기**: 나이키 런 클럽에서 내보낸 파일을 한 번 가져오는 import 스크립트를 우선 검토한다. 정기 동기화보다 안정적이다.
2. **공식 API 경유 연동**: Strava, Garmin 등 공식 API를 제공하는 서비스를 거쳐 기록을 가져올 수 있는지 먼저 확인한다.
3. **비공식 API 연동**: 약관과 안정성 위험이 있어 권장하지 않는다.

**근거**: 나이키 런 클럽은 공개 API가 없고, 비공식 exporter는 문서화되지 않은 엔드포인트에 의존한다. 사용자 계정의 데이터 내보내기는 일회성이며 수일에서 수주가 걸릴 수 있다. 최신 공식 정책은 확인하지 못했으므로 연동 전 재확인이 필요하다.
