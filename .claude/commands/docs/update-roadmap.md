대상: $ARGUMENTS

`docs/ROADMAP.md`에서 완료된 작업을 확인해 체크하고 Phase 상태를 갱신해주세요. 인자가 Phase 번호(1~5)면 그 Phase만, 비었거나 `전체`면 모든 Phase를 대상으로 합니다.

핵심 원칙은 ROADMAP 개요의 상태 표시 규칙입니다. **✅ 완료는 확인이 끝난 항목에만 씁니다.** 코드가 있다는 것만으로는 완료가 아닙니다.

## 절차

1. **현재 상태 읽기**
   - `docs/ROADMAP.md`에서 대상 Phase의 "상태", "할 작업", "완료 기준"과 맨 아래 "전체 순서 요약" 표를 읽습니다.

2. **증거 수집 (읽기 전용)**
   - `gh pr list --state merged`, `git log --oneline`으로 머지된 PR과 커밋을 확인합니다.
   - Shrimp `list_tasks`(completed)로 완료된 태스크와 요약에 적힌 검증 근거를 확인합니다.
   - `Glob`, `Grep`으로 항목이 말하는 파일과 코드가 실제로 있는지 확인합니다.
   - 완료 기준에 타입 체크나 lint가 있으면 `npx tsc --noEmit`, `npm run lint`를 실행합니다.
   - `npm run build`는 실행하지 않습니다. 개발 서버가 떠 있으면 `.next`가 깨집니다. 빌드 결과가 필요하면 사용자에게 `/check:all`을 안내합니다.

3. **항목별 판정**: "할 작업"과 "완료 기준"의 각 항목을 아래 셋 중 하나로 분류하고 근거를 한 줄씩 붙입니다.
   - **확인됨**: 항목을 직접 확인한 증거가 있습니다(머지된 PR, 완료 처리된 Shrimp 태스크의 검증 요약, 이번에 실행한 명령 결과). 근거를 같이 적을 수 있는 항목만 해당합니다.
   - **구현만 됨**: 코드는 있지만 완료 기준을 확인한 증거가 없습니다. 체크하지 않고 "구현됨, 확인 필요"로 보고합니다.
   - **미착수 또는 미확인**: 증거가 없습니다. 그대로 둡니다.
   - 증거가 코드의 존재뿐이거나 이전 세션의 기억뿐이면 "확인됨"으로 올리지 않습니다.

4. **Phase 상태 결정**
   - 모든 완료 기준이 ✅이면 `✅ 완료 (YYYY-MM-DD 확인)`
   - 일부만 ✅이거나 구현이 진행 중이면 `진행 중`
   - 아무것도 없으면 `미착수`
   - "전체 순서 요약" 표의 상태 열도 같은 값으로 맞춥니다.

5. **변경안 제시 후 승인**
   - 바꿀 줄을 `before → after` 형식으로 보여주고, `AskUserQuestion`으로 적용 여부를 묻습니다. 첫 번째 선택지는 "모두 적용 (권장)", 그다음 "일부만 선택", 마지막은 "적용 안 함"입니다.
   - **승인 전에는 파일을 수정하지 않습니다.** 변경할 것이 없으면 질문 없이 보고만 합니다.

6. **적용**
   - 승인된 항목만 `docs/ROADMAP.md`에 `Edit`로 반영합니다. 기존 표기를 그대로 따릅니다. 예: `- ✅ 항목 설명 (근거, PR #N)`, `**상태**: ✅ 완료 (2026-10-30 확인)`.
   - 날짜는 오늘 날짜를 씁니다. 추측하지 않습니다.
   - 수정 후 결과 줄을 다시 읽어 표기가 깨지지 않았는지(끝 공백이 사라져 문구가 붙은 경우 등) 확인합니다.

7. **보고** (표로 요약)
   - 확인됨, 구현만 됨, 미확인 항목 수
   - 바꾼 줄 목록(Phase별)
   - 아직 확인되지 않은 항목과 확인 방법(예: "노션 TEST 행 필요", "브라우저 확인 필요")
   - 로드맵 밖에서 추가된 작업(예: Shrimp에만 있는 태스크)이 있으면 별도로 알립니다.

## 규칙

- 수정 대상은 `docs/ROADMAP.md`뿐입니다. `docs/PRD.md`, 코드, `package.json`, `shrimp_data`는 수정하지 않습니다.
- 항목을 삭제하거나 순서와 문구를 새로 쓰지 않습니다. 상태 표기와 근거 문구만 바꿉니다.
- 새 항목이 필요해 보이면 수정하지 않고 보고에 제안만 합니다.
- 개발 서버를 띄우거나 노션을 변경하지 않습니다. 그런 확인이 필요한 항목은 "확인 필요"로 보고하고 사용자에게 넘깁니다.
- 커밋, push, PR은 요청받은 뒤에만 합니다.
